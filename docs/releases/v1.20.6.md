## The advisors work on your project, not on Solix's

Several of the fifteen advisors Solix installs into `~/.claude/agents` had been written for Solix's own repository, and every user got them:

- **Sentinel**, on by default, reviewed "Solix's attack surface": its `settings.json` patching, its server on 4242.
- **Helios** aimed for "60fps with 20 simultaneous planets".
- **Lumen** tuned the galaxy scene.
- **Forge** ran this repository's build command and guarded its router.
- **Delta, Mira, Atlas, Argus and Vale** pointed at this repository's files.

On any other project, they reviewed the wrong product.

They now read the project in front of them: its own build and test commands, its `CLAUDE.md` and `CONTRIBUTING.md`, its design system, its migration tool and its release process. Each keeps its role and output format.

**Tried on a different codebase.** The five default advisors were run on Solix's marketing site, a different stack. All five came back with specific, true findings:

- **Sentinel:** the FAQ claimed your code "never leaves your machine". Claude Code sends it to Anthropic.
- **Compass:** the FAQ contradicted itself about which sessions are gated.
- **Lumen:** a CSS rule erased the line joining the install steps.
- **Argus:** a missed component in a real pull request.
- **Forge:** built a sitemap test that fails when it should.

Each finding was checked and fixed, and they are now the "real finding" lines on the site's advisor cards.

**When you get them:** the first time you run `solix` after upgrading, it replaces the advisors it installed. Agent files you wrote yourself are left alone, as before.

Two smaller corrections: Compass no longer promises to write a backlog file (it has read-only tools), and the advisor manifest no longer calls Maestro "(Pro)", a tier that does not exist.

`CLAIM-ADVISORS-PORTABLE` lists ten traces of Solix's own code that may not appear in any shipped advisor. Run against 1.20.5's advisors, all ten fail.

## From an outside QA pass

An evaluator tested the site, the CLI and the demo as a new user on 2026-11-19, and three of their findings were in Solix:

- **One number for what is waiting on you.** They saw the rail say 3, the Decisions panel "4 waiting on you", and Mission Control "3 pending now". The panel counted a plan paused at its budget cap, and the other two didn't. All three now count held commands plus budget holds. `CLAIM-DECISIONS-ONE-COUNT`
- **`solix ledger --demo`.** Decisions you make in the demo were recorded in the demo's own sandbox, so `solix ledger` said "No decisions yet". `--demo` reads the sandbox, labelled as invented data, and plain `solix ledger` points there when its own record is empty. `CLAIM-DEMO-DECISIONS-IN-LEDGER`
- **The demo no longer suggests running the demo.** Inside `solix demo`, the welcome screen now gives a short tour instead: open Decisions and answer a held command, switch views, and read the ledger.

## `solix demo` names its agents in full, and starts clean

- **Agents are labelled `demo-05`, not `demo-05-`.** Every view labels a session by the first 8 characters of its id, and the demo's old ids were cut mid-word.
- **A demo that never shut down no longer leaks into the next one.** Closing the terminal skipped the cleanup, so the next `solix demo` reopened the old sandbox and seeded a second galaxy beside the first. Now a demo starts from an empty sandbox (unless you pass `--keep`), and closing the terminal shuts it down like Ctrl+C.
