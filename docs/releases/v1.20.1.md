A security fix for the approval rules in 1.20.0. **Upgrade if you use `solix rules defaults` or `solix gate`.**

**1,267 tests. 43 claims in `docs/CLAIMS.md`, each with a test that fails when it stops being true.**

## What was wrong

The rule matcher only recognised a path when a word *began* with `/` or `~`. A redirect target written straight after its operator was invisible to it. With the default rules in 1.20.0:

| Command | 1.20.0 | 1.20.1 |
|---|---|---|
| `echo hi >/etc/x` | **auto-allowed** | asked / refused |
| `echo hi >>~/.bashrc` | **auto-allowed** | asked / refused |
| `echo hi 2>/etc/x`, `&>/etc/x`, `echo x>/etc/y` | **auto-allowed** | asked / refused |
| `cat </etc/passwd` | **auto-allowed** | asked / refused |
| `cat x > /dev/null` | asked (a false hold) | allowed |

So a rule written for printing allowed a write anywhere on the machine. At the desk, nobody was asked. Under `solix gate`, the policy should have refused it and didn't.

**What was never exposed:** the containment denylist runs before any rule and was unaffected. `rm -rf /`, writes to SSH keys, raw block devices, `curl | sh` and `sudo` were refused as before. File-tool writes (`Write`, `Edit`) outside the project were also unaffected.

## The fix

- Every word is split on redirection operators (`>`, `>>`, `>|`, `<`, `<<<`, with an fd number or `&` in front, `&` after), and every target is judged as a path. A target outside the project is not covered by any allow rule.
- Discarding output is still allowed with or without a space: `>/dev/null`, `2>&1`, `>&2`, and the standard streams `/dev/stdout`, `/dev/stderr`, `/dev/stdin`. Any other device, like `/dev/tcp/…`, is outside the project.
- An assignment with a redirect (`S=x>/etc/y; ls`) is judged by its target too.

`CLAIM-RULES-SEE-REDIRECTS` holds this: 11 commands that reach outside the project must not be covered, and 10 that discard output or stay inside it still must be.

**Found by running it.** A `solix gate` run on a real Mac turned up a false hold on `> /dev/null`. Looking into why turned up the hole.

## Also

- `npm publish` no longer warns that it auto-corrected the `solix` bin path.

## Upgrading

```sh
npm i -g @shmulikdav/solix
solix start
```

Rules you have already added are unchanged. A command they covered in 1.20.0 that redirects outside the project is now asked about (or refused under `solix gate`) instead of allowed.
