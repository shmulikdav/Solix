Two features finished, four commands tested for the first time, and a set of numbers that were not true.

**1,050 tests. 26 claims in `docs/CLAIMS.md`, each with a test that fails when it stops being true.**

> **1.18.2 is included here.** It was changelogged but never published, so its fix — the one below — ships in this release. There is no `@shmulikdav/solix@1.18.2`.

---

## Your spend was counted again on every restart

`solix start` re-reads the tail of each transcript so the Chat tab opens with context. The cost accumulator ran over those replayed lines too, and the session's `cost_usd` was still in the database — so **every restart added the same messages on top of themselves.**

Measured, not inferred: a two-message transcript recorded **$0.1425, then $0.285 after one restart, then $0.4275 after two.** Exactly one extra copy per start, compounding. Mission token totals doubled the same way.

Worse than a wrong number on a screen: **budgets read it**, so "pauses before the spend crosses the cap" would pause work that had not cost that much. And a restart is not an edge case — it is what the 1.18.0 notes tell you to do after upgrading.

Each session now carries a persisted high-water mark, so a replayed line reaches the chat without being charged again.

### ⚠️ This release resets every recorded figure to zero, once

Nothing in the database distinguishes real spend from spend counted twice, so there is no migration that could correct them. A deliberate trade: genuine history is destroyed in exchange for numbers that visibly start over rather than being quietly wrong. It happens once and says so on startup.

## Both half-built features are whole

**Plan editing.** Each task row carries ↑ ↓ ✎ ×, and the editor exposes the title, the worker's prompt, the verifier's acceptance criteria and the model — labelled by *who reads them*, because swapping the prompt and the criteria is the mistake this newly makes possible. Building it found the route underneath would accept a rewrite of a **verified** task's acceptance criteria, which would have made "verified against its acceptance criteria" mean nothing.

**Routine editing.** A mistyped cadence used to mean delete-and-recreate, which drops the run history and rotates the webhook token. A patch keeps both. A cadence change states the new spend before the button that commits to it.

## Numbers that were not true

- **The context percentage was only ever real in the demo.** Nothing persisted it, so every advisor was told `context=0%` and the "⚠ CONTEXT NEAR LIMIT — run /compact" branch was unreachable. `solix demo`'s hardcoded 62 and 89 were the only writes in the product.
- **`solix ledger` stopped at 1000** audit rows of any kind and printed that as the window's total — including `**Decisions:** N` inside the **signed** fleet report.
- **Spend held at budget pauses was counted twice**, because that figure is cumulative and three code paths re-pause a plan with its budget untouched.
- **A session on a context window larger than the 200K anchor read a confident 100%**, which told the model to compact a session nowhere near full.

Where there is no measurement you now get an em dash, not a zero.

## Things that asserted what they had not observed

- **Agent View could tell you a running agent had finished.** A failed directory read made Solix mark every mirrored background session `terminated`, which the UI renders as **"Done"**. And a status string it did not recognise showed as a calm `idle`. Both fixed — the file's own PR-status mapper had been making the right call all along, fourteen lines away.
- **A routine you switched off still ran** if you clicked Run now: the fire route never checked `enabled`, while the webhook route for the same routine refused it. "Fired" was also reported over launches that were skipped or threw.
- **The timeline never fetched its most recent events** in a busy window — it took the oldest N and then kept the newest of those — so scrubbing to the end of a playback showed the system as it was minutes earlier, under a label saying "last 30 min".
- **Solix told machines with Claude Code installed to install Claude Code**, because it checked for `~/.claude` rather than the binary. Found by walking the install sequence against a packed tarball.

## An empty `SOLIX_PORT` could turn the gate off

Thirteen places read that variable, three different ways, and all three mishandled it being *set but empty* — so `SOLIX_PORT=` read as port **0**. `solix start` would bind a random free port and publish "0" to the hooks, which would call port 0, find nothing, and **fail-closed on every tool call**: safe, useless, silent. One strict-decimal parser now, in all thirteen.

## The galaxy leaked while you watched it

Every context update built a new compiled shader and nothing ever released it; every store event re-rendered every planet. The leak grew with **event volume rather than fleet size**, so thirty planets left running was enough.

## Verified against this tarball, not just in CI

Installed the packed build into a clean machine against a real `claude` 2.1.316 and walked the evaluation sequence: the gate held with the exact command, deny prevented it, **killing Solix mid-hold exited in 24ms** having refused the held call, and the canary survived all of it. `solix doctor --port` reported *All checks passed*, and the context percentage came back **19.547** from a real transcript — a field that was `0` for the life of every install before this.

Every fix was proven by reinstating its own bug and confirming the right test failed. **Nine of those proofs did not work first time** — the test had set up a case where the broken and the fixed code agree — and were rewritten until they failed for the right reason. A test that cannot fail is the same defect as a sentence with nothing behind it.
