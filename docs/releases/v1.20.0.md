The release that answers the review that called Solix a **PILOT**: at the default level every tool call was held, a person's "no" did not stick, and CI had no way to run under the gate at all.

**1,234 tests. 42 claims in `docs/CLAIMS.md`, each with a test that fails when it stops being true.**

> **1.19.0 was never published.** Everything planned for it ships here. There is no `@shmulikdav/solix@1.19.0`.

## A hold is the exception now

Measured on 1.18.3: a five-task plan at `standard` was held **thirty times for thirty tool calls**, `Read SPEC.md` included. People flip to `observe` when that happens, and then the gate is gone.

**Approval rules** are a person's standing decisions at the gate. They are consulted *after* the containment denylist, which no rule can override, and *before* anyone is asked. A rule's decision is recorded as the rule's, so the ledger never counts a rule firing a hundred times as a hundred people.

- `solix rules defaults` installs an opt-in set: read-only tools, writes inside the project, listing, testing, committing. Nothing that deletes, pushes, escalates or fetches.
- A shell command is allowed only when **every part** is covered, so `ls && git push --force` is not "an `ls`". Paths outside the project are never covered, and `$( … )` contents are checked as their own commands.
- **Always allow …** on a Decisions card writes the rule and approves the call. Fleet → **Rules** lists rules with hit counts.

**The number, stated honestly:** on the last measured run, holds went from **30 to 4**, with 27 calls decided by rules. Most of the remaining four were the agent touching its own session scratchpad, which is now covered too. That fix is proven by tests but **has not yet been re-measured on a real machine**, so this release does not claim a lower figure. `docs/EVAL.md` has the method and will carry the next measurement.

## A denial is a decision, not a question to ask again

- A command a person denies is refused for the rest of that plan without asking again.
- A task whose attempt a person denied is sent to a human instead of retried.
- A plan whose decision was still open when Solix stopped comes back **paused**, not resumed with the command decided by default.
- Lowering the governance level while workers are running needs `--force`.

## `solix gate` — the gate with nobody at it

```sh
solix gate --rules policy.json -- claude -p "…"
```

Runs any agent under a rules policy in CI, where nobody is there to answer. A call a rule allows proceeds; anything else is **refused at once** instead of held, and the agent is told to report what it needed rather than retry. The denylist still runs first. Afterwards it writes the audit and a **signed report**, and the run exits **3** if anything was refused. It never touches `~/.claude`.

**Verified on a real Mac with a real `claude`:** the refusal reached the agent word for word, the agent stopped instead of rephrasing, and each call was counted once. See `docs/GATE.md` for the policy format and a GitHub Actions example.

## Parallel Maestro, for independent tasks

Tasks the planner marks **isolated** — no dependencies, files disjoint from their siblings — now run at the same time, each in its own git worktree. Their changes merge back into the plan one at a time. If two "isolated" tasks touch the same file, the second goes to a person and nothing is silently merged. Plans without isolated tasks run exactly as before.

## Security

A web page using DNS rebinding could read local plan and session data, because the API never checked the `Host` it was addressed to. Every route and the websocket now answer only to a loopback name, `*.localhost`, or a name in `SOLIX_ALLOWED_HOSTS`.

## Found by running it

- **Hooks wired twice.** Starting Solix from a second `SOLIX_HOME` added a second set of hooks, so every call was held and recorded twice. A hook is now recognised by name, wherever it lives.
- **The gate counted twice** on a machine that also had Solix installed, for the same reason. Fixed.
- **A typo started Solix.** `solix gaet` started the server and wired `~/.claude`. An unknown command is now refused: `error: unknown command 'gaet' — did you mean 'gate'?`

## Numbers that were not true

- "**~2ms** per hook" was the cost of starting `sh`, not of the hook. Replaced with what is enforced: every hook caps its network call and fails open.
- "Shutdown in **24ms**" was one machine's best case. Now stated as a bound: well under a second, even with a browser tab open.
- `GET /api/plans/:id` now returns `spendUsd`, so a plan's budget can be shown against what it has spent.

## Upgrading

```sh
npm i -g @shmulikdav/solix
solix start          # updates the hooks
solix rules defaults # optional: the opt-in allow list
```

Nothing is reset. Rules are opt-in, so behaviour at the gate is unchanged until you add some.
