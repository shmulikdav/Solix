If you are on 1.18.0, upgrade and restart. The fix is entirely in the server process — no hook script changed — so what matters is restarting Solix, not re-wiring anything:

```
npm i -g @shmulikdav/solix@1.18.1
solix start
```

`solix doctor` will call your hooks stale until that start refreshes the install stamp. Their contents are identical to 1.18.0's; only the stamp moved.

## What was wrong

1.18.0 was installed from npm into a sandbox and `docs/PARTNER-BRIEF.md` was walked literally, in its own order, the way someone evaluating Solix would. The brief's step 2 is *kill the Solix server mid-hold*, and calls fail-closed "the property I would not ship without".

**Fail-closed held.** The canary file survived every single run; nothing destructive ever executed, at any point. That property was never broken and this release does not change it.

Everything around it was broken. `http.Server.close()` does not call back until every open connection has ended, and a held permission **is** an open HTTP request whose only possible answer is a human in a UI that is shutting down with it. So:

- **`Ctrl+C` did not quit while anything was held.** Solix printed `SIGINT — shutting down` and then sat there. The `await` never returned, so the `process.exit(0)` after it never ran.
- **The agent waited five minutes to be refused** — and not by the shutdown. By the gate's own 300-second backstop, firing inside a process that could no longer exit. The audit log recorded the hold opening at 17:01:41 and `Timed out after 300s and was denied` at 17:06:41.
- **An open browser tab caused the same hang by itself.** A websocket is a socket the HTTP server waits for too, and `closeAllConnections()` cannot reach it, because Node stops tracking a socket once it has been upgraded. Measured: a client with a 20-second lifetime held a signalled server up for 16.2 seconds. With the UI open — which is the state the brief puts you in — Ctrl+C waited on a tab nobody was looking at, even with nothing held.

## Why a passing test was hiding it

E6 in `docs/E2E-SMOKE-TEST.md` has covered "kill the server mid-decision" since 1.16.0, and it passed every time, because the only thing it ever checked was whether the canary file survived. It did. Nobody read the terminal.

`createSolixServer` had no test of any kind. It has three now, and each half of the fix was proven by reinstating its own bug: remove the hold-release and only the held case times out; remove the websocket teardown and only the open-tab case does. E6 is rewritten to assert on the terminal and the process, not just the file.

## Fixed

Shutdown now records each abandoned hold and drops the sockets. It deliberately does **not** answer the hook: the hook sees its connection fail and takes its fail-closed branch, so the agent is refused and told the gate was *unavailable* rather than that a person reviewed the command. Nobody reviewed it. Any hold at all means the session was launched above `observe`, which is exactly when the launcher injects `SOLIX_GATE_POLICY=deny`, so fail-closed is what that hook does.

Re-measured against a real agent, with a websocket held open for five minutes and a permission held: **222ms**, down from 300,000ms.

## Also

Nothing asserted that a `permission_request` arriving over the websocket actually produces a notification — the brief's step 3, "walk away mid-hold". The notifier and the `notify me` button were each well covered in isolation; the single line joining them was not, so deleting it broke no test. Four tests cover it now, and it was confirmed live in a real browser with notifications granted and the tab hidden.

Three claims in the partner brief were corrected while there: the test count, and `solix uninstall` "removes all of it" — it restores your Claude config byte-for-byte, which is the stronger promise, but it keeps `~/.solix` by design and says so.

799 tests.

## Known, and not fixed

Unchanged from 1.18.0: a `claude` session you started yourself is not governed and cannot be, since Solix governs an agent by setting its environment before the process starts. `solix run` and Agent View are the same story, and Codex has no gate. Share's publish/registry API has no UI, there is no selector memoisation at several hundred sessions, routines are not editable or org-scoped, and there is no responsive layout.

Full detail in [CHANGELOG.md](https://github.com/shmulikdav/Solix/blob/main/CHANGELOG.md).
