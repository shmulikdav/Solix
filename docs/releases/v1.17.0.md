> **Superseded.** This release claimed "every way Solix launches an agent is
> now governed". That turned out to be wrong in three ways, all fixed in
> [v1.18.0](https://github.com/shmulikdav/Solix/releases/tag/v1.18.0). If you
> are running 1.17.0, upgrade: your gate is off on a non-default port, has no
> floor for New tasks, and none at all at `observe`.
>
> These notes are backfilled, and say what 1.17.0 actually did rather than
> repeating a claim since disproved.

## What it changed

**A New task became gated.** It was the most prominent button in the UI and
the only launch path Solix never governed — it carried no
`SOLIX_GATE_ENABLED` at any level, so its hook never blocked and no decision
was ever raised. At `standard` and `strict` its risky commands are held like
anything else Solix launches.

It is **gated without being contained**. Containment bundles two things —
strip the environment to an allowlist, and inject the gate. That bundle is
right for an autonomous worker nobody is watching. It is wrong for a task you
launched and are sitting in front of: scrubbing would take away the keys and
tooling your own shell has, to protect you from yourself. Your environment,
held commands.

**Agent View is skipped for a gated launch**, and says so. `claude --bg`
hands the session to a supervisor that does not inherit the environment we
set when it is already running, so the gate would apply or not depending on
whether something else happened to start the daemon first. A guarantee that
holds nondeterministically is worse than one that is plainly absent.

**A test that reads the environment off the spawn itself.** With the env
builder tested and the Agent View decision tested, the fix could still be
deleted and every test passed — confirmed by reverting it. That is the shape
of every gate bug in this project: the layer below is right, the layer above
is right, and nothing checks the wire between them.

## What it missed

That last paragraph was more right than it knew. Three more of exactly that
shape were still in place and shipped in this release — see v1.18.0.
