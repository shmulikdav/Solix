**If you are on 1.17.0 or earlier, upgrade.** The approval gate — the thing
Solix exists for — was off in three different ways, and all three were
unit-tested and passing the whole time. They were found by running it against
a real `claude` with configurations nobody had varied, not by reading it.

```sh
npm i -g @shmulikdav/solix@1.18.0
solix start
```

The restart matters: the hooks on disk carry a version stamp, and `solix
doctor` will tell you they are stale until you do.

## The three

**`solix start --port N` disabled the gate entirely.** The hooks find the
server through `SOLIX_PORT`, defaulting to 4242. The flag moved the listener
and never set the variable, so every spawned agent's hook called 4242, found
nothing, and fail-closed on every tool call. Safe, and useless: the agent was
*blocked* rather than held, no decision card ever appeared, and the only
trace was `Solix gate unavailable (fail-closed)` inside a worker's report.
The port-conflict message added in this same release tells you to `--port`
your way out of a collision — straight into it.

**The denylist only guarded Maestro's agents.** `rm -rf /`, a fork bomb and
`curl | sh` were refused for workers and verifiers and nothing else, because
containment returned early for anything without a session role. A New task
has none. At `observe` it ran `sudo -n true` with nothing in its way; at
`standard` it was merely *held for a human*, which is a different mechanism
with a different promise. The README claimed the denylist applied "at every
level, in every one of those rows". It has four rows and the claim was true
for two.

**The floor sat behind a database lookup.** Containment ran only when the
session row was found, so a tool call whose session could not be resolved
skipped it: `{"decision":"allow"}` at `observe`. A session row is absent for
ordinary reasons — a hook arriving before `session-start` is processed, a
pre-created row that failed to write, a correlation miss.

All three are fixed, and `docs/E2E-SMOKE-TEST.md` gains **F8**: run the
denylist probe at all three levels every release. It had no live coverage at
all before this.

## A team install that doubled the bill

A team's routines are recurring spend. Installing one created them
unconditionally with an identical success toast both times, so a second click
left two enabled routines running the same prompt forever. They are
recognised and skipped now. The install failure reason was also being
discarded, and one checkbox answered for every team — on the control that
decides whether spend starts.

## And the layer around it

Solix was read the way a team evaluating it would read it, and scored 4/10.
That audit is also in this release: a malformed `~/.claude/settings.json`
could be replaced with Solix's hooks alone; approvals were never
acknowledged, so one dropped by a reconnecting socket looked identical to a
successful one; `terminate_session` was a bare `break;`; notification
permission was only ever requested while the tab was hidden, which is the one
moment browsers refuse to prompt; and Mission Control reported `$0.00` beside
real spend.

Full detail in [CHANGELOG.md](https://github.com/shmulikdav/Solix/blob/main/CHANGELOG.md).

## Known, and not fixed

A `claude` session you started yourself is not governed and cannot be — Solix
governs an agent by setting its environment before the process starts.
`solix run` and Agent View are the same story. Codex has no gate at all.
Share's publish/registry API has no UI, there is no selector memoisation at
several hundred sessions, and there is no responsive layout.

791 tests, up from 616 three days ago.
