Three things a beta tester would meet in their first ten minutes. All three were found by running Solix on a machine with months of history.

**1,402 tests. 51 claims in `docs/CLAIMS.md`, each with a test that fails when it stops being true.**

## The count was wrong, and the galaxy was full of ghosts

One machine's top bar read **"17 active · 464 idle"** with a handful of `claude` processes running. Solix doesn't install Claude Code's session-end hook, so a session ended only when someone pressed **Terminate**. Every `claude` that ever exited stayed "idle" forever, and one killed mid-turn stayed "active".

**Now:**
- At startup and every minute, Solix retires sessions whose process has ended. They stop counting and leave the galaxy.
- The end is dated to the session's last activity, not to the moment Solix noticed.

**Deliberately left alone:**
- Agent View sessions, whose supervisor owns them.
- Sessions still starting up.
- Any session whose reported process was already gone while its events kept arriving. That process isn't the agent's own (a hook run by a short-lived shell, or a session on another machine), so its absence proves nothing.

If a session is retired by mistake, it comes back on its next event.

`CLAIM-DEAD-SESSIONS-RETIRE` is tested against real processes, not a simulated liveness check.

## A galaxy you can read with a long history

- **Quiet history is hidden.** Idle sessions with no activity for over a day aren't drawn. The galaxy says so, for example "312 quiet sessions hidden · Show", and one click shows them. The choice is remembered.
- **Never hidden:** anything working, waiting on you, recently active, or selected.
- **List always shows everything.**

This matters most after `solix import`, which backfills idle sessions from your transcripts. Those have no process to check, so retiring dead sessions alone wouldn't clear them. `CLAIM-GALAXY-HIDES-QUIET`.

## Upgrading without `kill`

After `npm i -g`, the server that's already running keeps running the old version. A new `solix` used to say only "port 4242 is already in use", and the browser kept showing the old version, without the fixes you'd just installed.

```sh
solix stop && solix
```

- **`solix stop`** stops the running server. It only ever signals a process that answered as Solix, and Solix refuses anything it's holding before it exits.
- **A second `solix` on a busy port** now says what's there and what to do:

```
[solix] Solix 1.20.3 is already running on port 4242 (pid 4711), and this is 1.20.4 — nothing was started.
        The browser shows the running version, not this one. Replace it:
          solix stop && solix
```

`CLAIM-UPGRADE-NAMES-THE-RUNNING-SERVER`.

## Fixed

- `docs/CLAIMS.md` said Maestro's parallel limit defaults to 1. It's been 2 since 1.20.0. The text is corrected, and a test now pins the default, so the claim can't drift again.

## Upgrading

```sh
npm i -g @shmulikdav/solix
solix stop && solix
```

This works even from 1.20.3 or earlier. The `solix` you just installed is 1.20.4, and its `stop` finds an older server through `lsof`. If `lsof` isn't installed (some minimal Linux setups), it tells you to stop the old server with Ctrl+C in its terminal.

The first start retires every session left over from processes that have ended, which may be most of your history. They leave the galaxy and the counts. Their records stay in `~/.solix/solix.db`.
